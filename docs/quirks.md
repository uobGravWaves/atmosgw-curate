# Known quirks kept from the MATLAB code

Ports reproduce the MATLAB code exactly first, so they can be checked against
its outputs. Behaviour that is known to be wrong or questionable is kept, and
listed here so it can be fixed later. Each fix is a separate change with
before/after tests.

Each quirk has an ID, used in the code comments at the place where it
happens, and a test that pins the current behaviour. Fixing a quirk should
change that test and the matching MATLAB regression fields, and nothing else.

| ID | Where | What happens | Why it matters | Pinned by |
|---|---|---|---|---|
| Q1 | `atmosphere.py` (from `h2p.m`, `p2h.m`) | **Fixed 2026-11-25** (MATLAB and Python: `h2p.m` and `p2h.m` rewritten to implement the U.S. Standard Atmosphere 1976 [R1], from -5 to 149 km). Each layer between seven reference heights was treated as isothermal (one exponential), and the reference heights, which are the standard's geopotential heights (confirmed against the document), were used as geometric heights. | Compared with the standard, pressures from height were off by up to 15% at 60 km and 27% at 86 km, and heights from pressure (MLS altitudes) by up to 0.4 km near the stratopause, 1.1 km at 60 km and 1.7 km at 86 km. Every result of `h2p`/`p2h` changes, in the loader (MLS heights; pressure for ALOMAR, Misc and PW files) and in the other MATLAB code that calls them. | `test_atmosphere.py::test_table_i_pressures` and the other known-answer tests |
| Q2 | `atmosphere.height_to_pressure` (from `h2p.m`) | **Fixed 2026-11-25** (with Q1). Altitudes below 0 km gave NaN; now valid from -5 km, as the standard's Table I. | Low-lying data, or small negative altitudes from retrievals, got no pressure. | `test_atmosphere.py::test_range_and_invalid_input` |
| Q3 | `atmosphere.pressure_to_height` (from `p2h.m`) | **Fixed 2026-11-25** (with Q1). A pressure above 1013.25 hPa matched no layer and reused the layer of the previous finite element (in MATLAB, column-major order), or stopped with an error if it was the first. Now pressures up to 1777.6 hPa (-5 km) are converted, and higher ones give NaN. | The result for such a pressure depended on what came before it in the array. | `test_atmosphere.py::test_range_and_invalid_input` |
| Q4 | `geodesy.haversine` (from `nph_haversine.m`) | **Fixed 2026-11-25** (MATLAB `nph_haversine.m` and `nph_haversine_mars.m`, and Python): the intermediate value a is clipped to [0, 1], NaN kept. For points within about 1e-7 degrees of exactly antipodal, rounding could make a slightly greater than 1, so sqrt(1 - a) was undefined: NaN in Python, an error in MATLAB. | Only nearly antipodal points were affected; not reached by the limb-sounder loader. All other results are unchanged, bit for bit (checked on 1e6 random pairs in both languages). | `test_geodesy.py::test_q4_near_antipodal_gives_half_circle` |
| Q5 | `readers.find_files` (from `wildcardsearch.m`, `regexpdir.m`) | **Fixed in MATLAB 2026-11-25** (`wildcardsearch.m` now runs `clear regexpdir` before each search; `regexpdir.m`, third-party, is unchanged). Python never reproduced it. `regexpdir` kept the root folder of its first call in a MATLAB session (a `persistent` variable never reset), so later calls matched the pattern against the full path instead of the path relative to their own root. | Results could differ only if the root folder's own path matched the pattern (e.g. contained the date being searched for), and MATLAB's result then depended on what was searched earlier in the session. | `test_readers.py::test_matches_relative_path_and_folders` |
| Q6 | `obs/limb.py` (from `get_limbsounders.m`) | **Fixed 2026-11-25** (MATLAB and Python). Pressure was interpolated to the height scale linearly in height, like every other variable. It is now interpolated in log(pressure) [R3], except with `nearest`, `next` or `previous`. | Pressure falls roughly exponentially with height, so linear interpolation overestimated it between levels. On the MATLAB test dates (default height scale), the largest overestimates were MIPAS 11% (median 1.2%), MLS 1.9% (0.4%), ACE 0.5%, HIRDLS 0.12%, SABER 0.09%, and 0.02% or less for SOFIE, GNSS and ALOMAR. Only the output pressure changed. | `test_limb_known.py::test_q6_pressure_interpolated_in_log_pressure` |
| Q7 | `obs/_limb_alomar.py` (from `module_load_ALOMAR.m`) | **Fixed 2026-11-24** (MATLAB: MultiInstrumentFunctions commit e13e247; Python: same day). The heights of the first day in each yearly file were used for every day. In the 2007 file, 37 of the 58 days (from 2007-05-14) have a different grid: 766 levels from 5.10 km instead of 765 from 5.25 km, so on those days every temperature was placed 0.15 km (one level) too high, and the top level had no height. Each day's own `z_lidar` is now used. | Interpolated temperatures on 2007-06-01 changed by a median of 0.39 K (up to 15.6 K). The MATLAB reference cases (2007-01-23, the file's first day) are unchanged. Other years not checked. | `test_limb_known.py::test_q7_alomar_each_day_has_its_own_heights` |
| Q8 | `obs/_limb_mls.py` (from `module_load_MLS.m`) | **Fixed in Python 2026-11-25; MATLAB unchanged.** When more than one file matched a day, the first in name order was used. In the group's MLS folder (November 2026), 155 days of 2026 have both a v05-04 file and a v06 file, so v05-04 was used on those days and v06 on the others: a 2026 time series switched data version from day to day without notice. The newest version is now used, and any day with more than one matching file (any instrument) is listed in the output attribute `multiple_matches`, with a warning. Other instruments still use the first match, as MATLAB. | On 2026-01-01 to 03, v06-04 instead of v05-04: 10,452 profiles instead of 10,497 (10,360 at the same times); temperature on the default height scale changes by a median absolute 0.2 K at 20 km, 0.9 K at 40 km and 1.5 K at 60 km (95th percentile 0.4, 2.5 and 4.8 K). Days with one file are unchanged, bit for bit. | `test_limb_known.py::test_q8_mls_newest_version_used_and_recorded` |
